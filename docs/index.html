Orchestrator of Three Cycles

Does having AI agents argue with each other produce better code fixes than a single AI working alone?

Quick Start

Get up and running in under 2 minutes.

Prerequisites

  • Python 3.12+
  • uv package manager
  • Git repository to work on

Install Dependencies

uv sync --all-extras

Add API Key (Optional)

cp .env.example .env
# Edit .env with your NIM key
💡 No API Key? No Problem

Run without --nim flag to use built-in fake models for testing the flow.

Installation

Clone the Repository

git clone https://github.com/anujsingh-cse/orchestrator-of-three-cycles.git
cd orchestrator-of-three-cycles

Install uv (if not installed)

# macOS / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh

# Windows (PowerShell)
irm https://astral.sh/uv/install.ps1 | iex

# Or via pip
pip install uv

Install Project Dependencies

uv sync --all-extras

Verify Installation

uv run orchestrator --help

You should see the help output with all available options.

Basic Usage

Command Structure

uv run orchestrator "your task description" [options]

Available Options

Flag Description Default
--repo PATH Path to repository Current directory
--nim Use NVIDIA NIM models (needs API key) Off (fake models)
--api-key KEY NIM API key Reads from .env
--tui Use Textual TUI interface Plain text streaming
--auto-approve Auto-approve human gate Reject (human must approve)

Use Case: Local Git Repository

Fix bugs in any local git repository on your machine.

# Navigate to your repository
cd /path/to/your/repo

# Run the orchestrator
uv run orchestrator "fix the login timeout bug" --repo . --auto-approve
💡 Tip

The --repo . uses the current directory. You can also use absolute or relative paths: --repo ../other-project

Requirements

  • Directory must be a git repository (.git folder exists)
  • Repository should have a test suite (pytest by default)
  • Code should be in a language the models understand (Python, JS, TS, Go, Rust, etc.)

Use Case: GitHub Repository

Clone and fix bugs in any public or private GitHub repository.

# Clone the repository
git clone https://github.com/owner/repo.git
cd repo

# Run the orchestrator
uv run orchestrator "fix the memory leak in data processor" --repo . --auto-approve

For Private Repositories

# Clone with SSH (if you have SSH keys set up)
git clone git@github.com:owner/private-repo.git
cd private-repo

# Or use HTTPS with token
git clone https://ghp_yourtoken@github.com/owner/private-repo.git
⚠️ Private Repos

Make sure your Git credentials are configured. The orchestrator uses the repository as-is — it doesn't manage auth.

Use Case: Non-Git Codebase (Any Files)

The orchestrator requires a git repository. For non-git folders, initialize git first:

cd /path/to/your/code

# Initialize git (one-time setup)
git init
git add .
git commit -m "initial commit"

# Now run the orchestrator
uv run orchestrator "add error handling to parser" --repo . --auto-approve
💡 Why Git?

The tool uses git worktrees for isolation — each patch is applied in a disposable clone so your original code is never modified until you approve.

Use Case: Real AI Models (NVIDIA NIM Free Tier)

Use production-quality models for real fixes. Free tier available.

Get Your Free API Key

Use Case: Interactive TUI Mode

Visual terminal interface with live streaming updates.

uv run orchestrator "fix the race condition" --repo . --tui --auto-approve

TUI Features

  • Live token streaming from each agent
  • Visual flow diagram with current node highlighted
  • Session log with expandable details
  • Keyboard shortcuts (Q to quit)
⚠️ Terminal Requirements
  • Needs a proper TTY (not all CI terminals work)
  • Minimum 80x24 terminal size
  • Use plain mode (--tui omitted) for CI/scripts

    • Use Case: Human Approval Mode (Default)

    Review each patch before it's applied to your codebase.

    uv run orchestrator "add input validation" --repo .

    What You'll See

    [coder] patch 247 chars
[adversary] 3 keys
[critic] 2 keys
[arbiter] verdict=pass escalated=[]
[HITL] Approve applying this patch?
> Type 'approve' or 'reject'

    Type approve to apply the patch and run tests, or reject to stop.

    💡 When to Use

    Use human approval for production codebases. Use --auto-approve for experimentation and CI.

    What Happens When You Run It

    1
    You Run Command
    Task description + repo path + options
    ▼
    2
    Coder Proposes Fix
    Generates a unified diff patch for the task
    ▼
    3
    Adversary Attacks
    Finds edge cases, security holes, logic errors in the patch
    ▼
    4
    Critic Judges
    Decides: PASS (fix works) or ESCALATE (needs human review)
    ▼
    5
    Human Gate (HITL)
    You approve/reject (or auto-approve with flag)
    ▼
    6
    Runner Applies & Tests
    Applies patch in isolated worktree, runs test suite
    ▼
    7
    Loop or Done
    If tests fail → back to Coder (max 5 rounds). If pass → done.

    Every step is recorded in an audit log (SQLite) that can be replayed exactly.

    Output Explained

    Plain Text Mode (Default)

    [coder] patch 247 chars
[adversary] 3 keys
[critic] 2 keys
[arbiter] verdict=pass escalated=[]
[HITL] Approve applying this patch?
[gate] decision=approve
[record_gate] 1 keys
[runner] patch 0 chars
[done] session finished

    What Each Line Means

    Line Meaning
    [coder] patch N chars Coder produced a diff of N characters
    [adversary] N keys Adversary found N attack vectors
    [critic] N keys Critic evaluated N criteria
    [arbiter] verdict=X Final verdict: pass, escalate, patch_fix, etc.
    [HITL] ... Human-in-the-loop approval prompt
    [gate] decision=X Gate recorded your decision
    [runner] patch N chars Patch applied (0 = clean apply)
    [done] session finished Session complete

    Key Terms

    Term Definition
    Falsification Loop The 3-agent debate cycle: Coder → Adversary → Critic
    HITL Human-In-The-Loop — the approval gate
    Worktree Isolated git clone where patches are tested
    Audit DAG Directed acyclic graph of all events (SQLite)
    Verdict Critic's judgment: pass, escalate, patch_fix, replan, etc.
    Pacing Rate limiting per model to avoid API 429 errors
    Draft Model Local Ollama model for fast speculative execution

    Environment Variables

    Create a .env file in the project root (copy from .env.example):

    # Required for --nim mode
NIM_API_KEY=nvapi-your-key-here

# Optional: custom NIM endpoint
NIM_BASE_URL=https://integrate.api.nvidia.com/v1

# Local Ollama (alternative to NIM)

OLLAMA_DRAFT_MODEL=qwen3:8b

    Variable Reference

    Variable Required Description
    NIM_API_KEY For --nim NVIDIA NIM API key from build.nvidia.com
    NIM_BASE_URL No Custom NIM endpoint (default: build.nvidia.com)
    OLLAMA_HOST No Ollama server URL (default: localhost:11434)
    OLLAMA_DRAFT_MODEL No Local model for draft/routing (default: qwen3:8b)

    Model Roster

    Models are auto-configured based on verified availability (updated 2026-08-18):

    Role Model Purpose RPM Limit
    Coder nemotron-3-super-120b-a12b Fast code generation 47
    Adversary nemotron-3-ultra-550b-a55b Deep adversarial reasoning 16
    Critic nemotron-3-ultra-550b-a55b Judgment & evaluation 16
    Draft Ollama (qwen3:8b) Local speculative execution Unlimited (local)
    ℹ️ RPM Limits

    Per-model rate limits measured on NIM free tier with 80% safety margin. The pacer automatically handles 429 responses with exponential backoff.

    Advanced: Specific Branch

    cd /path/to/repo
git checkout feature-branch
uv run orchestrator "fix the bug" --repo . --auto-approve

    The orchestrator works on the currently checked-out branch. Changes are applied to that branch's worktree.

    Advanced: Custom Test Command

    Default test command: pytest -q -x

    To customize, edit src/orchestrator/runner/process.py:

    def run_tests(
    worktree_root: Path,
    timeout_s: float = 120.0,
    command: list[str] | None = None  # <-- customize this
) -> TestResult:
    cmd = command or ["pytest", "-q", "-x"]

    Or fork the repo and modify the runner for your test framework (Jest, Cargo test, Go test, etc.).

    Advanced: Audit Log

    Every session creates an audit database:

    your-repo/.orchestrator/audit.db

    Query the Audit Log

    # View all events
uv run python -c "
import sqlite3
conn = sqlite3.connect('your-repo/.orchestrator/audit.db')
for row in conn.execute('SELECT node, ts, gate_decision FROM events'):
    print(row)
"

# View session tree
uv run python -c "
import sqlite3
conn = sqlite3.connect('your-repo/.orchestrator/audit.db')
for row in conn.execute('SELECT id, parent_event_id, node, model_id FROM events'):
    print(row)
"

    Schema

    CREATE TABLE events (
    id TEXT PRIMARY KEY,
    parent_event_id TEXT,
    thread_id TEXT NOT NULL,
    node TEXT NOT NULL,
    agent_id TEXT NOT NULL,
    model_id TEXT NOT NULL,
    ts TEXT NOT NULL,
    input_hash TEXT NOT NULL,
    output_hash TEXT NOT NULL,
    payload_in TEXT NOT NULL DEFAULT '{}',
    payload_out TEXT NOT NULL DEFAULT '{}',
    tool_calls TEXT NOT NULL DEFAULT '[]',
    tokens_in INTEGER NOT NULL DEFAULT 0,
    tokens_out INTEGER NOT NULL DEFAULT 0,
    gate_decision TEXT
);

    Troubleshooting

    "Not a git repository"

    git init
git add .
git commit -m "init"

    "NIM_API_KEY required"

    # Use fake models (no key)
uv run orchestrator "task" --repo . --auto-approve

# Or add key to .env
echo "NIM_API_KEY=your-key" > .env

    "Textual not installed"

    uv sync --extra textual
# Or use plain mode (default)

    Tests fail after patch

    The loop continues automatically (up to 5 coder rounds). If it keeps failing, the adversary may have found a fundamental issue.

    Stale audit.db

    rm your-repo/.orchestrator/audit.db
# Re-run - creates fresh schema

    Permission denied

    # On Linux/macOS
chmod +x .venv/bin/orchestrator

    Architecture Overview

    ┌─────────────────────────────────────────────────────────────┐ │ CLI Entry Point │ └──────────────────────────┬──────────────────────────────────┘ │ ┌─────────────────┼─────────────────┐ ▼ ▼ ▼ ┌────────────────┐ ┌────────────────┐ ┌────────────────┐ │ Adapters │ │ Graph │ │ Audit │ │ (LLM Seam) │ │ (LangGraph) │ │ Sink │ │ │ │ │ │ (SQLite DAG) │ │ - NIM │ │ - Coder │ │ │ │ - Ollama │ │ - Adversary │ │ - Write-ahead │ │ - Fake │ │ - Critic │ │ - Integrity │ │ - Pacing │ │ - Arbiter │ │ - Replay │ └────────────────┘ │ - Gate (HITL) │ └────────────────┘ │ - Runner │ └────────────────┘ │ ▼ ┌────────────────────────┐ │ Worktree │ │ (Isolated Git Clone) │ └────────────────────────┘

    Component Responsibilities

    Adapters (P4 Seam)

    Provider-agnostic LLM interface. NIM, Ollama, and Fake implementations with pacing circuit breaker.

    Graph (T3)

    LangGraph state machine with conditional edges, HITL gate, and verdict-based routing.

    Audit Sink (D2/D7)

    Fail-closed SQLite write-ahead log. Content hashing for replay determinism. Chain verification.

    Runner (D5/D8)

    Git worktree isolation. Env scrubbing (secrets removed). Timeout kill on test hangs.
